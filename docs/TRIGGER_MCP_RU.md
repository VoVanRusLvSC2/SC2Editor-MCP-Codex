# GUI-триггеры MCP и модель AST

`trigger.plan` создаёт родной XML `Triggers`. По умолчанию всё находится в корне карты, без отдельной библиотеки ресурсов. Конвертер не изменён и не используется. Модель элементов и каноническая сериализация перенесены из нашего AST-проекта; исходные файлы и SHA перечислены в `generated/trigger-ast-reuse.json`.

## Типы и переменные

Поддержаны все 83 конкретных кода из предоставленного словаря GUI. Остальные 10 — void и контекстные/обобщённые правила, а не самостоятельные объявления переменных. Типы `dialog`, `control`, `sound`, `portrait`, `unitfilter`, `wave`, `filepath`, типы атрибутов и остальные сохраняют своё GUI-имя; они не подменяются универсальной строкой. Специализированные значения задаются вызовом подходящей функции/ссылкой; произвольные числовые литералы для живых объектов не принимаются.

Переменная: `name`, `type`, `scope` global/local, `initial`, `constant`, `arraySizes`, `gameType` для gamelink и `typeElement` для preset/struct. `typeElement` принимает имя или ID и библиотеку. Собственные типы сначала объявляются через `presets`/`structures`, либо разрешаются из объявленной зависимости.

```json
{
 "structures":[{"name":"PlayerState","fields":[
   {"name":"score","type":"int"},
   {"name":"history","type":"int","arraySizes":[4]}
 ]}],
 "variables":[
   {"name":"PlayerCount","type":"int","constant":true,"initial":{"kind":"literal","type":"int","value":8}},
   {"name":"States","type":"struct","typeElement":{"name":"PlayerState"},"arraySizes":[{"variable":"PlayerCount"}]}
 ]
}
```

Константа получает нативный `VariableType/Constant`. Её нельзя записывать или использовать как изменяемый итератор. Константные инициализаторы допускают литерал, пресет и ранее объявленную константу; произвольный вызов не допускается. Размер массива — положительное целое или ссылка на глобальную int-константу. В API доступны до четырёх измерений (наблюдаемая форма GUI, не заявление о универсальном пределе всех внутренних массивов). Для буквального индекса проверяются тип, знак и известная граница; динамический индекс требует int. Неиндексированный массив не выдаётся за скаляр.

Чтение/запись `States[2].history[1]`:

```json
{"kind":"variable","name":"States","indices":[{"kind":"literal","type":"int","value":2}],
 "members":[{"field":"history","indices":[{"kind":"literal","type":"int","value":1}]}]}
```

Эта ссылка подходит для `SetVariable.var`, выражения и аргумента. XML содержит цепочку `Variable`, `Array Type=Param` и `StructMember Type=Param`, как в AST. Поля записи остаются членами Structure, а не глобальными переменными. Тип и наличие поля проверяются; прямые/взаимные рекурсивные записи отклоняются.

## Пресеты

`presets`: name, baseType int/fixed/bool/string, values с name/value/default, integer, asBits, generateConstants. Обычный пресет сохраняет явные значения; ordinal использует `PresetInteger`, без произвольно подставленных чисел; битовый — `PresetAsBits`. Допускается один default. Идентичность Preset сохраняется: два пресета с одинаковыми числами не считаются одним типом.

```json
{"presets":[{"name":"Mode","baseType":"int","values":[
 {"name":"Easy","value":1,"default":true},{"name":"Hard","value":2}
]}],"variables":[{"name":"CurrentMode","type":"preset","typeElement":{"name":"Mode"},
 "initial":{"kind":"preset","preset":"Mode","name":"Easy"}}]}
```

Битовая комбинация: `{kind:"presetBits",preset:"Flags",values:["Ground","Air"]}`. Доступны собственные и подключённые пресеты. `trigger.types` выдаёт короткую страницу типов, пресетов и записей с полями.

## Пользовательские определения

`functions` поддерживает Action, Condition, Event и Function. Есть типизированные параметры, локальные переменные, calls и returns. У Condition результат bool, у Function результат задаёт returnType. Параметр внутри тела — `{kind:"parameter",name:"value"}`; он также поддерживает members/indices, когда тип это допускает.

Параметры поддерживают default, limits в нативном формате `min,max`, reference, multiple, variableOnly. Для Multiple аргумент может быть массивом GuiValue; каждый элемент получает собственный Param с тем же ParamDef ID. Пустой список операторов отклоняется. Не переданный аргумент берётся из сохранённой цепочки Default; она не заменяется произвольным нулём.

Дополнительные опции определения: CreateThread (только Action), Hidden, NoScriptPrefix, grammar, hint. Существующие прочие флаги читаются из библиотек. Restricted, CustomAI и CustomScript не объявляются доказанной универсальной поддержкой; Inline без установленного нативного представления не создаётся.

Вызовы по имени или ID; `custom:Name`/`native:Name` снимают конфликт, `Lbty::Name` явно выбирает библиотеку. Прямые/взаимные рекурсивные пользовательские вызовы отклоняются. Примеры четырёх ролей и сигнала: `examples/triggers/custom-gui-functions.json`.

## CASC и библиотечный индекс

Для проекта приложения загрузчик проверяет текущий Core по SHA/build, читает DocumentInfo и рекурсивно подключает только объявленные зависимости. CASC materializes настоящие SC2Lib/triggerlib/root Triggers и строки; LibraryList выбирает активные библиотеки. Установленная, но не объявленная библиотека не становится доступной автоматически.

Индекс сохраняется сжато по отпечатку источников и восстанавливается в новом сеансе. Проверяются XML, пространства library/type/id, отсутствие конфликтов и циклов. Материализованные файлы сопоставляются с оригинальными CASC-хешами. Новый ensurePackage переиспользует полностью проверенный mount, без повторного обхода всего пакета. При plan/apply проверяются изменения DocumentInfo, библиотек, NativeLib, строк, объектов и каталогов. Игра остаётся источником только для чтения.

NativeLib 98310 совпал с нашим профилем по SHA. Закреплённый индекс дополнен из AST: ReturnType/TypeElement/GameType, пресеты, 407 переменных и Default-параметры. Для использования GameLink автоматически подключаются необходимые объявленные каталоги; отсутствие/частичность источника остаётся ошибкой.

## Экономия текста и бенчмарк

Локальные функции сборки находятся в `src/modules/trigger/builder.ts`: integer/real/boolean, variable/parameter/preset, call/action/event/condition, at/member. Они возвращают тот же строгий план; дополнительная библиотека в карте не появляется. ID и XML модель пишет сама. Пакеты описываются коротким JS, а в контекст возвращаются сводки и страницы, не весь индекс.

`node scripts/benchmark-trigger-authoring.mjs` создаёт три одинаковые задачи в Galaxy и GUI: стартовые ресурсы, доход с массивом, запись с массивами/пресетом/константой/действием. Затем `python scripts/count-trigger-benchmark-tokens.py` считает o200k_base через tiktoken (установить его локально в work/trigger-ast-completion/tokenizer).

Отдельно учитываются Galaxy, короткий исходник GUI builder, JSON и XML. Время — структурная проверка/запись Galaxy и plan/apply/save GUI, один холодный и пять тёплых повторов в одном клиенте; сброс не включён. Это не время генерации LLM, не реальные токены тарификации/рассуждения и не время исполнения игры. GUI-IR сверяется независимой симуляцией; внешний AST-парсер дополнительно читает XML через виртуальное пространство Map, без изменения сохраняемой карты. Компиляция SC2 в этом тесте не выполняется.

## GUI и исполняемый скрипт

`Triggers` — дерево GUI; игра исполняет `MapScript.galaxy`. После изменения GUI редактор должен сгенерировать и сохранить соответствующий скрипт. MCP-план не объявляется Galaxy-компилятором. Это исправляет прежнее неверное ожидание, что наличие GUI само по себе запускает события.

Существующая Agria_GUI_Ready содержит предоставленный пользователем компилированный скрипт; пользователь подтвердил сообщение и атаки. Новые AST-конструкции проверены программно и на доступности настоящих CASC-источников, но пока не имеют отдельного подтверждения компилятором/игрой. Управление SC2 Editor не выполнялось; конвертер не менялся и не запускался.

Прежние graft, normalizeScriptLayout, get/inspect/apply/save/discard сохранены. Полные схемы произвольных raw ExpressionText/ValueParam и восстановление любого неизвестного Galaxy остаются отдельной задачей конвертера.


## Офлайн-сборка и экономный транспорт

`trigger.plan_file` принимает один GuiRequest или массив запросов из JSON внутри workspace. Массив строится на изолированном staged-снимке: исходные файлы и drafts вызывающего проекта не меняются. Итог применяется одним `trigger.apply`, сохраняется одной группой. `trigger.describe_functions` возвращает до 40 компактных сигнатур с ограниченными списками пресетов.

`trigger.generate_runtime` генерирует MapScript из самого XML-графа и проверяет его до staging. Нет дублирования ручного Galaxy и нет вызова конвертера. Поддерживается явный поднабор: map-root структуры, массивы, простые пресеты, функции/условия/действия/события, if и целочисленные циклы, стандартные вызовы. Неизвестные шаблоны, потоки и пользовательский сырой код прекращают генерацию; это не полный компилятор Galaxy. Поля получают префикс, поэтому `wave` не превращается в ключевое слово. Размеры массивов читаются из VariableType/ArraySize и соответствуют физическим размерам редактора.

Кастомное Event получает неявный `trigger t`. Для вызовов регистрации внутри его тела создаётся скрытая нативная сигнатура с явным первым аргументом t; ресурсная Library не создаётся. Единственный внутренний ScriptCode-параметр содержит выражение t, а не пользовательский скрипт. Проверка реальным компилятором остаётся отдельной.

`trigger.recipe_skirmish` параметризует сохранённый рецепт миссии вместо повторной передачи большого JSON. Нужны существующие Objects IDs, способность и UI-шаблон. `ui.recipe_timer`, `ui.assets.register`, `ui.assets.save`, `ui.hookup.validate` создают/регистрируют только пользовательские стили, DescIndex и компоненты font/uiui. Штатные стили наследуются из Core.

Профиль SC2_MCP_PROFILE=map-builder сокращает начальный список схем. Остальные инструменты доступны через modkit.tools и modkit.enable_tools; профиль all сохранён. modkit.usage измеряет аргументы и текстовые ответы MCP через o200k_base и длительность обработчиков. Тексты не пишутся в журнал; фактические токены модели, рассуждение и биллинг недоступны.
