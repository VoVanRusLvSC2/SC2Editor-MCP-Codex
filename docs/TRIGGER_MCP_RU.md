# GUI Triggers через MCP

Модуль `trigger.*` доступен в профилях `script`, `authoring` и `all`. Он работает с распакованным корневым файлом `Triggers` и общими транзакциями Workspace.

1. `trigger.inspect` — список идентификаторов, ID, событий и действий; `query`, `offset`, `limit` ограничивают вывод.
2. `trigger.get` — XML одного триггера и определения его событий/действий.
3. `trigger.graft` — перенос одного `Event` или `Action` по индексу из другого файла `Triggers`, расположенного **внутри того же workspace**. Копируются локальные зависимости узла, конфликтующие ID переназначаются. По умолчанию операция возвращает dry-run diff; `dryRun:false` создаёт черновик.
4. `trigger.save` сохраняет черновик с проверкой изменений на диске; `trigger.discard` его отменяет.

Пример переноса события из файла, созданного Trigger Revizer KSP, в исходное дерево карты:

```json
{"sourceFile":"revizer/generated.xml","sourceTrigger":"Resourceschange","targetTrigger":"Resourceschange","kind":"Event","index":0,"dryRun":true}
```

После проверки повторите вызов с `dryRun:false`, затем вызовите `trigger.save`. В отличие от полной регенерации библиотеки перенос сохраняет существующие категории, ID триггеров и ключи локализации. Перенос `Action` копирует его локальный граф XML, но смысл ссылок на внешние определения и результат компиляции Galaxy следует проверить в SC2Editor. Инструмент не запускает редактор и не выполняет игру.
