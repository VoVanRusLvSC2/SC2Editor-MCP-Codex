Terrain Native Teams

terrain.cliff.paint, terrain.ramp.create, terrain.ramp.remove They work through a common plan/apply/save, and they keep the components in a single group. Profile: terrain v115, unit scale, even grid, rectangular grid cliffs 2 cells, levels 0-3, cardinal ramp 4 width at adjacent levels 1→2 or 2→3. Diagonal/arbitrary ramps and unknown hard-tile handles are rejected. This is a limited profile, not the entire geometry of the editor.

The base of the relief and the cliff channel are separated. A conventional brush changes the heightBase, retaining the heightAdjustments. When you transition the old procedurally edited flat map to the native Terrain, the heights are saved and transferred to the old misused channel. Water, hidden cells and unknown high flag bits are preserved.

Optimization

  • packet trigger.describe_functions Limits presets and does not output all XML/defaults.
  • trigger.plan_file reads the declarative JSON and builds a single, unchanging plan; the original drafts do not change during planning; and terrain/settings/document.plan_file is added.
  • trigger.generate_runtime It uses the GUI graph as its only source; the supported subset is checked before writing. Unknown flow control, code templates, threads, raw scripts, and unsupported libraries give a clear failure.
  • trigger.recipe_skirmish and ui.recipe_timer Reuse mission/UI instead of large re-marking.
  • CASC looks for the exact folders of the package, eliminates nested cards, merges types/locales of cache. The real Liberty Campaign mounted without PACKAGE_NOT_MOUNTED in about 7 seconds. Current bytes and SHAs are checked.
  • Data checks XML for immutable text, the tree is built lazily; IDs checks do not deploy all object fields. Terrain for water/light uses directories instead of a wide Browse; protection from external files is saved.
  • ui.assets.register/save, ui.hookup.validate Check registration and communications. placement.geometry_check Checks heights of all forms of Objects XML, borders and intersection candidates on InnerRadius.Exact mesh-sampling/Footprint/engine pathfinding is not declared ready.
  • modkit.usage It maintains time handlers and accurate text o200k_base MCP argument/response tokens. The counter works in a separate worker and does not block handlers. There is no query/response text in the log.
