# Reusable map tests through MCP

## Current release evidence gate

This is a developer gate for a complete repository/source checkout. Run
`npm run build` first. An explicit `--root` must name that complete context,
including the pin, indexed records and declared source files. Default execution
from a portable package layout is unsupported and is not claimed here. The public
portable `project.quality.plan` keeps its separate unavailable/unverified source
semantics; this strict release gate does not invent missing-source matches.

`npm run evidence:check` uses the same digest and source-scope inventory as
quality discovery. It requires all declared required coverage, explicit current
native acceptance and separate human art approval. Missing release selection is
not ready (exit2); invalid digests, paths or schemas fail (exit1).
`--integrity-only` checks readable, valid evidence without claiming acceptance.
It never turns partial, stale or unsupported coverage into passed.

The versioned `index.currentRelease` is an optional object with `schemaVersion:1`,
a scoped relative `file` and that file's `sha256`. The selected binding has
`schemaVersion:1`, a `runtime` containing the exact pin's `version`,
`nativeProtocol` and `archiveSha256`, plus `nativeRecord` and `artRecord` IDs.
Both IDs must name digest-verified scoped records in the same index. Historical
records cannot substitute for current acceptance. Binding fields cannot omit
or redefine the inventory's required coverage gates.

The native record adds `releaseAcceptance.native` with `schemaVersion:1`, the
same exact `runtime`, and independently declared `live` and `adapter` states.
The art record adds `releaseAcceptance.art` with `schemaVersion:1`, `state`,
`humanApproval`, a nonempty `scope` and the human `reviewer` for approval.
States are `passed`, `failed`, `partial`, `unsupported` or `not_checked`.
Native acceptance requires both states passed and matching declared source
scope. Art acceptance requires passed, explicit human approval, a named reviewer
and matching source scope. These are curated evidence declarations, not values
inferred from test counts or generated by the checker. No passing binding is
created by this change.

Keep old record hashes and source fingerprints unchanged. The former checker is
retained byte-for-byte as `scripts/check-verification-evidence-legacy.mjs` for
explicit historical diagnostics; its old current-pin/source assertions are
expected to fail against newer releases. Do not refresh old evidence to satisfy
them. A reviewed dependency scope must include relevant shared implementations,
schemas, adapters and runtime identity. Matching a smaller arbitrary file list
does not establish native equivalence.

## Bounded quality discovery

`project.quality.plan` reads digest-bound coverage declarations and explicit
bindings to existing test manifests. It does not start native workers, lease a
bridge or execute a suite. Compact syntax is `project quality.plan file=quality.json`.
Without a bindings file it returns bounded coverage status with unbound areas.
`coverage`, `bindingIds`, `offset` and `limit` select at most eight bindings.

A workspace-local bindings document has `version:1` and up to64 `bindings`:

```json
{
  "version": 1,
  "bindings": [{
    "id": "forest",
    "label": "Forest outpost refinement",
    "scope": "Existing named routes and overview; final art remains separate",
    "coverage": ["owned_landscape_workflow"],
    "directory": "Forest",
    "manifest": "acceptance.json",
    "records": [],
    "requiredViews": ["overview"],
    "expectedInputs": {},
    "expectedSources": {}
  }]
}
```

`directory` is contained in the current workspace. Manifest map/dependency paths
retain that directory as their root, exactly as in the existing runner. Optional
`expectedInputs` maps relative manifest/map/dependency filenames to SHA256 values;
`expectedSources` maps package-relative code paths to SHA256 values. Empty or
missing fingerprint baselines remain unbound. Source fingerprints can name
compiled `dist/` files when an installed package omits TypeScript sources.

Each row reports missing prerequisites, source/input drift and the existing
`project.test.plan` handoff with its workspace. The returned CLI argument array
uses the current runner with `--repeat 2`; `--live` is deliberately absent.
Use the planner in the returned workspace. Its original preflight, exact saved
artifact identity, failure-stop policy and cleanup remain authoritative.

Matching binding hashes establish freshness only. They never turn a partial
coverage category into passed, establish an unexecuted test result or approve
artwork. The default index comes from this installation's documentation; optional
`indexFile` uses an explicitly scoped workspace index. Missing original source
files in a portable package make the corresponding passed declarations
unverified. Record digest tampering and paths escaping their roots reject.
Responses are bounded; full logs and binary ownership preimages are excluded.

The developer `npm run evidence:status` CLI shares this inventory implementation.
Run `npm run build` first. Its strict mode still rejects missing source files;
MCP discovery separately retains unavailable source scope without inventing a
matching source. Hash reuse is limited to one inventory invocation, with no
cross-request acceptance cache.

Planning measures free space on the suite-output and configured private game
volumes without creating folders or connecting native clients. The budget covers
known private archive copies, capture/report allowances and one 256 MiB reserve per
physical volume. Same-volume roles combine their budgets. This is a bounded
preflight, not a prediction of all native Editor/Game storage growth.

Insufficient or unreadable space prevents readiness. The runner rechecks before
queueing and again before a queued job writes files or leases native bridges. If
space disappears while queued, the failed checks remain available through
`project.test.report` with `reportPersistence:"memory_only"` and no report-file
path; no snapshot directory or native session is created for that job. Normal
completed results use `reportPersistence:"workspace_file"`. Space is never freed
by deleting maps, evidence or another session's files automatically.

The developer `verify-toolkit-integration.mjs` runner also preserves each returned
tool response in `transcript.ndjson`, case transitions in `cases.ndjson` and an
atomic `checkpoint.json`. An interrupted verifier can retain completed observations
without its final report. A running checkpoint is not acceptance; inspect the
actual process and the final digest-bound result before treating a suite as passed.
These journals do not restart workers or modify the private Toolkit.

`project.test.*` composes the existing retained Editor and game bridges. A workflow
lease blocks conflicting mutable native commands during a test. Local status/job
inspection remains available. Runs open private archive copies, detach their game
sessions and release the bridges for the next map. They do not create new bridge
instances or close shared frontends after every test. Server shutdown drains the
runner before closing the frontends.

Planning reads the source archive's bounded MapInfo entry when routes, formations,
placement or pathing predicates need named points. Outside centers/member offsets
and unreadable bounds prevent `ready:true` before any Editor or Game job is queued.
This preflight does not certify a footprint or navigation. The runner separately
rechecks the exact native-saved artifact before game launch; source bounds cannot
substitute for metadata changed by native save. MapInfo byte caches are keyed by
the whole archive digest. Compact batch responses retain `ready`, `jobId`, state
and phase so callers can stop blocked plans and poll owned jobs without full logs.

Separate MCP processes use distinct retained worker/session directories, even
when they share a workspace. Repeated tests in one process reuse its same bridges
and directories. This prevents session-file collisions between chats; it does not
remove the Editor/game's own system resource or concurrency limitations.

Native Editor artifacts may use a short private `SC2_NATIVE_WORK_ROOT`; map
inputs and suite reports remain workspace-contained. A native-saved archive is
read through the retained bridge's exact worker boundary, checked against its
returned byte count and digest, copied into the suite and independently loaded
and compiled before game launch. Foreign and sibling-worker outputs remain
rejected. External storage is not permission to import arbitrary local files.

The CLI accepts repeated `--manifest <relative.json>` arguments. It plans and
executes these maps sequentially in one MCP process, retaining the same bridges.
`--repeat 2` repeats each manifest before moving to the next. A failed check remains
in the report and exit code; an unresolved plan stops the sequence before launch.
Use `--entry <compiled-index.js>` to select an explicitly frozen MCP build; the
default remains this checkout's `dist/index.js`. Maps still run through MCP.

## Native placement queries

`game.pads` declares up to32 named placement predicates for existing Unit catalog
IDs. It requires an explicit `game.nativeProbe` (or legacy `game.padProbe`)
and named points inside the saved
MapInfo playable interval. Placement/probe coordinates and search ranges must be
exactly representable on the native1/4096 fixed grid. Only points used by this
suite are constrained; unrelated route points keep their existing rules.

```json
{
  "points": {"pad": {"x": 32, "y": 44}, "probe": {"x": 16, "y": 16}},
  "pads": [{"id": "depot", "at": "pad", "type": "SupplyDepot",
            "owner": 1, "range": 0, "expected": "exact"}],
  "padProbe": {"origin": "probe", "afterGameSeconds": 1, "timeout": 30}
}
```

These are fields inside `game`, alongside other suites. `expected` is `exact`
(the default), `candidate` or `blocked`. A candidate expectation can declare
`maxOffset`; it does not become exact placement. Even range0 can snap the
request. Results retain both coordinates, exactness and measured offset.
Default native predicates retain power/creep restrictions. An explicit integer
`tests` mask requires `overrideReason`; tests0 bypasses normal restrictions and
is never chosen silently. An invalid catalog ID is unsupported, even when the
expectation is blocked. Missing/late native evidence stays inconclusive.

The runner uses existing Data/Script transactions to create a private query-only
archive, preserving unrelated payloads and the ordinary source digest. A unique
invisible helper type encodes the complete result page after **all** predicates
have executed in one declared elapsed-game-time callback. Helpers are not
placement blockers for later predicates. This archive contains no Game Toolkit
implementation and is never adopted as the ordinary tested/deliverable map.

The same retained Game bridge launches and closes this dedicated query pass
before any ordinary route/action/scenario pass. Native source, query artifact,
cleanup and build checks remain separate. A pad-only suite with capture and
launch diagnostics disabled needs no second ordinary launch. Observations apply
to the source map's state at the declared callback; they do not certify a build
order, resources, tech, every footprint, path arrival or visual quality. The
encoded response does not provide an exact query timestamp or engine binary
resource identity. These limits remain explicit in evidence.

## Native point pathing predicates

`game.pathing` adds up to32 explicit ground-point predicates to that same private
query pass. Use `game.nativeProbe` for shared timing/origin; the legacy `padProbe`
alias remains accepted when the suite contains pads. Supplying both aliases
rejects. The probe must have at least one placement or pathing check. All used
points are named, exact native1/4096 values below1000 and within MapInfo bounds.

```json
{
  "points": {"low": {"x": 16, "y": 32}, "high": {"x": 32, "y": 32},
             "probe": {"x": 12, "y": 12}},
  "pathing": [
    {"id": "lowGround", "kind": "passable", "at": "low", "expected": true},
    {"id": "highGround", "kind": "passable", "at": "high", "expected": true},
    {"id": "noRamp", "kind": "connected", "from": "low", "to": "high",
     "expected": false}
  ],
  "nativeProbe": {"origin": "probe", "afterGameSeconds": 1, "timeout": 30}
}
```

These are fields inside `game`. `kind:"passable"` calls the original
`PointPathingPassable`; `kind:"connected"` calls `PointPathingIsConnected`.
Every expected boolean is explicit. Checks retain the actual result, requested
points, function name and response artifact. IDs share the suite namespace.
Pathing checks use channel3; pad-only suites retain channel2. The largest mixed
page has97 helpers and is read as one complete native page. No partial page,
missing helper, timeout, unavailable read or false default is accepted as an
expected false. All placement/pathing queries execute before any helper exists.

Do not equate connectivity with passability of an occupied endpoint. The
qualified native profile has reported a connected occupied point that is not
passable. Neither predicate certifies a particular unit's footprint, facing,
movement plane/abilities, arrival or an obstacle cause. It does not rebuild
navigation and does not establish the state of a later separate ordinary Game
pass. In particular, an expected-blocked movement timeout remains inconclusive;
it is never upgraded by an earlier point query. Use the distinct native predicate
verdict for an explicit topology question, and movement for actual arrival.

## Reusable action observations

`game.actions` adds bounded before/action/event/after checks to a map manifest.
Existing `game.scenarios` are still forwarded unchanged to the SDK as one batch,
including their upstream `$ref` semantics. Action checks have their own local
`$from` scope, shared with `modkit.batch`; they do not split those SDK batches.

Scenario `expect` paths follow the SDK, rather than JavaScript property access.
The pinned dev.11 SDK returns a missing value for a list's `units.length` path.
Use numeric paths such as `units.0.valid`; with a two-result query, an explicit
`units.1:null` check can assert the second result is absent. Inspect the retained
list as well when accepting cardinality. Local action-check query expectations
use the MCP resolver and do support array `length`. Do not rewrite upstream
scenarios or silently drop an unsupported expectation to obtain a pass.

```json
{
  "id": "pulse",
  "before": [
    {"id": "caster", "method": "game.units.find",
     "arguments": {"type": "Caster", "owner": 1, "limit": 2},
     "expect": {"units.length": 1, "units.0.alive": true}},
    {"id": "target", "method": "game.units.find",
     "arguments": {"type": "Dummy", "owner": 0, "limit": 2},
     "expect": {"units.length": 1, "units.0.alive": true}}
  ],
  "action": {"method": "game.order", "arguments": {
    "unit": {"$from": "caster.units.0.id"}, "action": "ability",
    "ability": "Pulse", "command": 0,
    "target_unit": {"$from": "target.units.0.id"}
  }},
  "events": [{"id": "hit", "match": {
    "kind": "damage", "source": "galaxy", "amount": 40,
    "unit": {"$from": "target.units.0.id"}
  }}],
  "after": [{"id": "health", "method": "game.units.inspect",
    "arguments": {"unit": {"$from": "target.units.0.id"}},
    "expect": {"unit.life": 460}}]
}
```

An entry has `id`, optional `required` (default true), `before`, `action`,
`events`, optional observation `timeout`1..120 and `waitForComplete`, and `after`.
There are at most16 entries and16 queries per before/after phase. Query IDs use
letters/digits/underscores and are unique within the entry. Their structured
response bodies are available through `$from`; after checks can also reference
`observation`. Forward, unsafe, duplicate and upstream `$ref` links reject.
Queries support status, unit find/inspect, selection, camera and UI inspection.
They never submit hidden orders, fixture mutations or UI clicks.

The action delegates once to the retained bridge's `game.action`, under the
existing workflow lease. This preserves paged baselines, source-caster binding,
stream/time checks and default ability completion. Event `kind`/`source` are
explicit literals; remaining exact scalar matches may use `$from`. UI activation
uses `game.ui.activate` and actual inspected control IDs. Verify callback state
in `after`; a handler return or event alone is not a gameplay/art verdict.
Query `expect` paths use exact structured equality, without coercion or arithmetic.

An unconfirmed action blocks later action entries, with explicit inconclusive
verdicts and no submissions. Ambiguous submission stays `unknown`; it is never
retried. Legacy scenarios and their earlier committed effects remain intact.
Complete replies, action requests/observations and each result are private JSON
receipts. Missing bridge support is unsupported, not a simulated success.

The [scoped native action record](verification/reusable-action-checks-2026-10-23.json)
retains five actual launches, real Dialog callback readback, ordinary ability
damage/completion/energy and a three-page baseline after128 explicit fixtures.
The earlier UI clock-envelope failure remains recorded. This confirms the stated
fixtures and event profiles; it does not certify every UI control or overlapping
cast attribution, visual effects or complete diagnostic coverage.

Launch checks retain a bounded upstream reason, native status, runtime error flag
and map-confirmation state. For `map_compile_failed`, evidence also retains up to
three bounded `Script compile error:` summary lines with file/line information.
Adjacent source-code context and complete injected scripts stay in the private
response artifact. An unconfirmed Galaxy handshake is inconclusive,
including an upstream tool error carrying that explicit status; it cannot pass
acceptance. It does not establish a script compilation failure. Explicit native
failures remain failed and unsupported requests remain unsupported. The runner
still detaches owned sessions and does not run gameplay after unconfirmed launch.
Before detaching an unconfirmed launch, the runner makes one bounded read-only
`game.debug.inspect` request with `open:false` and records its response in
`launch_debug.json`. This never opens the debugger, changes focus or injects
input. Its optional inconclusive/unsupported check cannot certify map execution
or replace the launch result. An unavailable debugger does not prevent cleanup.
It also requests one UI-inclusive owned-process frame. A valid bounded PNG is
stored as `Launch.png` with its digest and an explicit diagnostic purpose; this
can show a loading/error screen, not proof that the requested map ran. A passed
image transport check never upgrades an unconfirmed launch. Capture failures
remain optional/inconclusive. Cancellation skips these extra diagnostic calls.
Set `game.launchDiagnostics:false` to skip these requests. Upstream capture errors
remain visible with a bounded reason and a private response-artifact path. A transport exception
during attach does not trigger further calls to a possibly broken connection.

## Entry points

1. `project.test.plan({file:"tests/routes.json"})`, or an inline `manifest`, resolves
   a saved map and explicit file dependencies without starting a worker.
2. `project.test.run({planId})` explicitly starts a queued job. The operator's
   `SC2_GAME_ALLOW_LAUNCH=1` configuration still applies.
3. `project.test.status({jobId})` reads compact progress. A running native handler
   remains running until actual completion; cancellation is cooperative.
4. `project.test.report({jobId,offset:0,limit:10,includeImage:false})` pages evidence
   and checks source, tested archive, manifest-file and explicit dependency digests against disk.
   `includeImage:true` returns the final native PNG as an MCP image block. Add
   `viewId:"overview"` to select a named `game.views` image instead; delivery
   verifies its recorded digest before returning pixels.
5. `project.test.cancel({jobId})` requests orderly cancellation and cleanup.

Profiles containing `game` or `editor` expose these tools. Direct native commands
remain available outside a leased workflow. Compact authoring supports
`project.test.plan file=tests/routes.json` and `project.test.status jobId=...`.
Running or cancelling through `modkit.author` requires explicit stage/save mode;
plan mode cannot launch a test.

## Manifest

Coordinates must come from the actual map; this example has no universal defaults.
Editor settings optionally select `renderBackend` (`auto`, `legacy` or `vulkan`);
the same selection is used when revalidating a native-saved game artifact.
Optional `scope` and `locale`, plus `contextLabel`, disambiguate the native GUI
root or library, including during exact-artifact revalidation. Planning requires
a nonblank actual `contextLabel` for explicit compilation and for
`gameArtifact:"native_saved"`, which implicitly recompiles the saved artifact.
Missing context blocks before worker startup; supplying an invented name does
not prove that context exists. Native check failures
retain a bounded phase error in the compact report. The Toolkit's GUI generation
pipeline requires a real authored context; an empty GUI tree with separately
connected Galaxy is not native-GUI compile acceptance. See
[native compilation scope](NATIVE_EDITOR.md).
Game settings independently accept `renderBackend` with the same choices and
forward it to the retained GameToolkit on each map launch.

`game.ready` can select a named unit by `type`, optional `owner` and XY `area`
(`xmin`, `ymin`, `xmax`, `ymax`). Optional `state` declares exact native `life`,
`shields` or `energy` values. The runner inspects up to 16 returned candidates per
poll and rechecks alive/valid, type, owner, area and declared vitals. This allows a
map's actual callback marker to establish readiness without a fixed delay.
It is a scoped unit-state condition, not proof of general launch stability.

Prepare exact-value markers before measuring them: check native vital maxima,
regeneration and any behavior that changes the chosen property. An expected
value above the native maximum is clamped, and a regenerating unit does not
retain an exact life value until the next poll. Keep intentional test-only Data
overrides in a separate fixture and identify the resulting archive. Preserve the
original failed runs instead of accepting the clamped number or changing a
precise assertion into an unexplained tolerance. For preplaced buildings, use
observed native pivot positions when bounding a search: footprint snapping can
move the engine pivot from the authored XY position. Retain type, owner and
exact one-object checks when correcting a search area.

Readiness by unit existence/vitals does not establish that its owner is an active
participant. Compare the live `game.attach` / `game.status` player roster before
issuing normal orders. Create intended participant slots through `settings.*`;
units placed for a live `None` player can still be found while orders do not
execute. Deliberate neutral/inactive-player tests need their own expectations.

For an event expected during map startup, inspect retained history with
`game.events`, or establish a cursor before the action being tested. Omitting the
cursor from `game.wait` starts a new baseline; it does not replay that history.
For a baseline before an action, consume `game.events` pages until `hasMore` is
false and retain that response's `cursor`. Continue from returned cursors; never
skip unread pages using `latestCursor`. Reusing a cursor from the first retained
page can match an earlier damage event. Check the matched caster and event time
against the new order as well as the amount/target.
For direct interactive checks, `game.action` now performs that drain, one order
and exact time/caster-bound observation under a single retained-bridge queue.
It waits for native ability completion by default and retains private receipts;
see [action observation](NATIVE_GAME.md#one-action-and-its-observed-events).
It is separate from the upstream `game.test.run` scenario vocabulary.
For serial ability casts, also await the native ability `complete` phase before
the next order when the design requires completion. A projectile can deal damage
while its caster is still finishing; zero cooldown alone does not establish
readiness. Preserve deliberate interruption tests separately. Ability completion
is a mechanics observation, not proof of a particular model animation.
A cursor sampled after readiness can already include the startup event, so
waiting only after it can time out despite correct map behavior. Keep event
identity and resulting map state as separate assertions.

Declare `game.startupEvents` to observe positive occurrences that may happen
before readiness. Each entry has a distinct `id`, exact scalar `match` fields
(nonempty `kind` and `source` are required), a real-time `timeout` in seconds
(1..120, default 20) and optional `required` (default true). For example:

```json
"startupEvents": [{
  "id": "startupDeath",
  "match": {"kind": "unit_died", "source": "galaxy", "unitType": "Marine", "owner": 1},
  "timeout": 8
}]
```

After readiness and before routes/scenarios, the runner reads `game.events`
without a cursor, drains retained pages using their returned `cursor` (never
`latestCursor`), then polls that continuation for future events. All declarations
share the same stream; their deadlines are independent. It never decodes or
constructs opaque cursors or uses `game.wait` to replay history. Reports retain
the matched event, page receipt, session/epoch/map-load identity and dropped flag.
A stream identity change invalidates the combined observation. Missing metadata,
nonadvancing history pages, the 256-page bound or an unobserved event at its
deadline stays inconclusive. A directly observed positive match can pass despite
retention loss, with `retentionComplete:false`; this does not certify full event
coverage or the absence of other events. Keep callback state assertions in a
separate ordinary scenario; an event occurrence alone does not prove that the
map's handler produced its intended result.

Before launching a suite with ground routes, the runner reads neutral MapInfo
from the exact selected archive and checks the used route point centers against
its playable interval (left/bottom inclusive, right/top exclusive). A point outside
the interval fails before game launch. Unsupported metadata is reported as a
required unsupported check, never accepted as valid terrain. Unit footprint
clearance, engine pathing/collision and buildability remain separate checks.
MapInfo is read with the bounded native component API without unpacking map assets,
then cached by the complete archive digest within the retained test runner.

The planner also checks the native terrain load structure with bounded neutral
`t3Terrain.xml` / `t3SyncHeightMap` reads. For the measured aligned identity
v114/v115 profile it checks allocation counts, dimensions and Q12 geometry.
Known invalid structure blocks planning before either native bridge starts.
Unsupported transforms remain optional/unverified and are preserved. Results
are cached by the complete archive digest; a selected native-saved artifact is
checked again with its own digest before launch. This is not a pathing check.

`terrain.load.inspect` reports the component-level diagnosis. The explicit
`terrain.load.repair` plan supports only the diagnosed legacy v115 level-one
generator defect: an all-zero SMAP scale and/or missing empty cliff allocation.
Apply/save uses the ordinary guarded terrain transaction. It preserves surface
payloads, objects and gameplay. Other transforms and authored cliff topology
are refused; a successful structural repair still needs an exact-archive test.

```json
{
  "version": 1,
  "map": "Maps/MyMap.SC2Map",
  "label": "Main entrance",
  "dependencies": [{"id": "MyMod", "file": "Mods/MyMod.SC2Mod"}],
  "expectedGameBuild": "5.0.17.98310",
  "editor": {"checks": ["load", "compile"], "contextLabel": "MAIN", "required": true},
  "game": {
    "ready": {"type": "Marine", "owner": 1, "timeout": 20},
    "points": {"outside": {"x": 40, "y": 48}, "inside": {"x": 48, "y": 48}},
    "routes": [{"id": "entrance", "from": "outside", "to": "inside", "type": "Marine", "mobility": "ground", "bidirectional": true, "timeout": 20}],
    "views": [{"id": "overview", "camera": {"x": 44, "y": 48, "distance": 55, "pitch": 60, "yaw": 180}}],
    "capture": true
  }
}
```

The schema supports bounded assertion scenarios, exact build-specific diagnostic
exceptions and negative Editor fixtures (`expected:"compile_failed"` or
`"load_failed"`). Scenario steps use allowed `game.test.run` methods and explicit
assertions; they cannot attach, detach or invoke arbitrary methods. Native Data
owns ability mechanics; scenarios issue orders and observe those mechanics.

`game.record` is a separate native operation, not a permitted nested scenario
step. Use a separate recording milestone instead of inserting it as a delay.
For event-driven assertions, obtain a cursor with `game.events` before the
action and inspect `game.wait`'s returned matched event object. Match actual
localized UI text and verify callback state separately from click acceptance.

Up to eight named `game.views` entries capture repeatable native viewpoints after
routes/scenarios. Each supplies explicit camera target, distance, pitch and yaw;
UI is excluded unless `includeUI:true`. The runner requires a finite native camera
readback within 0.5 world units/degrees (yaw wraps), then a bounded native PNG.
Missing readback/image remains inconclusive; a mismatched camera fails. Every
image retains its digest and `visualReview:"not_checked"`: successful camera and
capture operations do not establish good framing, visible content or art quality.
Use overview and gameplay-scale views, then inspect the returned pixels.
`scripts/run-map-tests.mjs --view overview` delivers that image through MCP and
verifies its digest; `--image` without `--view` retains final-frame delivery.

Routes create test-owned fixtures, check their actual spawn position/type/life,
issue an ordinary move, sample trajectories and confirm arrival. Each direction
uses a fresh fixture. Cleanup checks invalid-unit readback. When enabled, route
frames are captured before cleanup. An invalid/displaced spawn is a prerequisite
failure, not a pathfinding verdict. Combat, death or missing observation prevents
an arrival claim.

Movement samples retain the same response's `gameTime`, session, runtime epoch
and map-load serial, alongside request/response timing. Orders retain their raw
bounded receipt. Complete monotonic clocks produce observed game seconds per
wall second; missing fields stay unavailable/partial and contradictory identity
or regressing clocks make arrival correlation inconclusive. No extra status
poll is added. Group clock intervals start at the last member's order response;
their sequential reads are not an atomic snapshot. These measurements do not
identify configured game speed, FPS, load or an obstruction. The original real
time deadline remains unchanged, and an endpoint first observed after it cannot
pass. A slow simulation does not automatically earn extra time or a retry.

For a ramp or gate that could be bypassed, set route `maxDeviation` in world
units. Every sampled unit center, including the initial position, must stay
within that distance of the closed segment between the declared endpoints.
An observed detour fails even if arrival succeeds. Evidence records the maximum
observed deviation and sample count. This checks sampled centers, not the full
engine path, unsampled motion or footprint clearance; omit it for intentionally
curved routes or split those routes into meaningful segments.

### Concurrent ground groups

`game.formations` checks two to eight distinct fixtures separately from single-unit
routes. Each entry declares a common ground unit type/owner, named `from`/`to`
anchors and world-XY `offsets`; offsets are preserved at both endpoints and do
not rotate automatically. MapInfo containment covers every offset endpoint before
game launch. Runtime inspection must confirm each fixture's identity, owner,
type, life/shields and actual spawn. No flying-unit substitution is allowed.

All ordinary move orders are submitted before waiting. A pass needs every member
inside its own arrival tolerance, plus at least two still-in-transit member centers
changing between observation batches. Final positions alone, sequential passages,
timeouts and missing observations cannot certify concurrent movement. Life/shield
loss makes interference explicit. Optional `maxDeviation` checks each member's

unsupported/incomplete checks prevent acceptance. An observed failed assertion
