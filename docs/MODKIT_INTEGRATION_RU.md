# ModKit: Data, CASC и превью карты

Наш MCP использует публичные Host/SDK и загрузчик SC2 из [ModKit](https://github.com/hometlt/ModKit) и [ModKit-Blizzard](https://github.com/hometlt/ModKit-Blizzard). `map.preview` использует их world renderer, а не техническую картинку `terrain.preview`.

Установка дополнительного локального runtime: `npm run modkit:setup` из корня проекта. Нужны Node.js 22+, Git и доступ к npm/GitHub при установке. Ревизии зафиксированы: Core `72253b49adff4f572c4763cd1ca5c980264afe41`, Blizzard `78104889bed092d901516044bd90734df8d5caac`. Платформенные пакеты берутся из vendor-архивов Blizzard; их SHA256, ревизии исходников и хеш патча записаны в `.modkit-runtime/ModKit-Blizzard/sc2-mcp-runtime.json`. Это не автоматическое обновление на произвольный HEAD.

После установки перезапустите MCP. `modkit.runtime` показывает состояние. Для другой директории runtime есть `SC2_MODKIT_HOME`; для установленной игры — `SC2_CASC_ROOT`. Редактор и игра при работе этих инструментов не запускаются.

## Команды

```json
{"tool":"map.preview","args":{"directory":"MyMap","output":"both","mode":"render","includeImage":true}}
```

Результат: отдельный HTML с lossless gzip-сжатием встроенных данных с WebGL, исходными моделями/текстурами, вращением, масштабом, перемещением и выбором объекта/координат. PNG по умолчанию показывает геометрию (`render`); `topdown` даёт обзор с условными обозначениями объектов. Размер CPU-кадра ограничен 768×768; его освещение, тени и постобработка отличаются от GPU. HTML сохраняет настоящий WebGL renderer ModKit. Паритет с движком SC2 не сертифицирован. `modelFacets` отдельно считает модели с геометрией, материалами, скелетом, анимациями и текстурами: успешное преобразование файла само по себе не доказывает правильную картинку. `cliffPieces` и `rampPieces` считают размещённые модели уступов и рамп.

```json
{"tool":"data.modkit.query","args":{"directory":"MyMap","refs":[{"namespace":"Unit","entityId":"Marine"}],"fields":["LifeMax","Race"]}}
```

Это эффективные значения из оригинального ModContext ModKit, с цепочкой зависимостей, наследованием, массивами, источниками и незагруженными модами. `view: "authoring"` возвращает авторский индекс; `view: "exists"` — наличие; `view: "ids", namespace: "Unit"` — страницу идентификаторов. Передавайте `fields` и небольшие `refs`, чтобы получать меньше текста. Формат полей принадлежит ModKit. Существующие `data.plan/apply/save` сохраняют свой проверенный путь записи и не подменяются этим чтением.

После установки привычные `casc.search`, `casc.file.inspect`, `casc.read_text`, `casc.read_bytes`, `casc.mount` используют reader ModKit. `SC2_CASC_BACKEND=native` выбирает прежний CascLib; `modkit` требует установленный runtime, без скрытого отката. Content/encoding keys берутся из публичных методов `CascReader.resolveFile/resolveContentKey`; дополнены только отсутствовавшие TypeScript-декларации этих уже существующих методов. Прежняя MD5-проверка content key и SHA256 нашего кэша сохранены. Флаги локали и nameType этим адаптером не публикуются: нулевые значения не следует считать фактическими native-флагами. Один полный файл этого адаптера ограничен 64 MiB. CDN отключён.

В профиле `workflow` инструменты доступны через `modkit.tools`, `modkit.enable_tools` и `modkit.batch`. В `map-builder` `map.preview` и `data.modkit.query` доступны сразу. По умолчанию возвращаются пути и краткая диагностика; изображение добавляется только с `includeImage: true`.

## Состояние и ограничения

Используется один адаптер и один каталог ContentSources для Data и карты. ModKit сам читает MPQ/CASC и определяет порядок зависимостей. Сохранённые входные байты копируются в отдельный пакет с SHA256; предпросмотр не меняет исходную карту. Несохранённые текстовые черновики следует сохранить. Чтения сериализуются; повторный просмотр той же карты использует сохранённую геометрию. Изменение карты, сборки CASC и настроенных каталогов зависимостей меняет ключ кэша. Кэш снимков на диске пока не имеет автоматической уборки.

Совместимость публичных ревизий исправляется изолированными патчами. `scripts/modkit/compatibility.patch` отключает только дополнительную публикацию RLE-метаданных обзора сетки, API которой нет в опубликованном Core; геометрия и рисование родного обзора сохранены. Для hidden paths используется предыдущая сигнатура VFS с рекурсивным обходом. Патч также дополняет декларации двух существующих публичных методов CASC Reader, без изменения их реализации. Отдельный `platform-patches.mjs` исправляет URI преобразованных UVM, как описано ниже. Остальные ошибки сборки не игнорируются. `complete: false`, отсутствующие ресурсы и отсечённые слои не превращаются в успех с полной поддержкой.

Лицензии и авторство ModKit сохраняются. Runtime содержит оригинальные исходники и notices; M3 имеет части GPL-2.0-only. Локальные результаты могут содержать ресурсы установленной игры, они не добавляются в Git. Runtime устанавливается отдельно от стандартного Windows portable-пакета; установщик и адаптер входят в пакет. Точные параметры и совместимость нужно проверять по `modkit.runtime`.

## Что оставлено нашим

Интеграция ограничена CASC, чтением Data и `map.preview`. Существующие модули не заменяются целиком. «Лучше» ниже означает конкретную сохранённую возможность; общего превосходства одного проекта над другим эти проверки не доказывают.

| Часть | ModKit | Сохранено в нашем MCP |
|---|---|---|
| Data | ModContext: зависимости, эффективные значения, наследование и источники полей | `data.plan/apply/save`, проверка схем, транзакции, предварительная проверка и запись существующим способом; выбор полей и ограничение размера ответов для ИИ |
| CASC | Reader установленной игры на Node.js; общий каталог ресурсов для Data и карты | проверка активной сборки до/после чтения, исходного MD5 content key, SHA256 кэша, безопасные пути, существующие mount/reference-команды |
| CASC metadata | Ключи content/encoding подтверждены; флаги локали API не возвращает | CascLib сохранён через `SC2_CASC_BACKEND=native`: фактические localeFlags и альтернативный нативный reader. Нули адаптера ModKit не выдаются за native-флаги |
| Карта | Реальная world-сцена, исходные модели, текстуры, нативные cliff/ramp pieces | Создание карты, TERRAIN, размещение объектов и запись карты остаются нашими; HTML/PNG и MCP image подключены через общий адаптер, чтение использует неизменяемый снимок |
| Работа ИИ | Библиотечные API | `modkit.batch`, выбор инструментов, короткие ответы, ограниченные выборки и повторное использование уже загруженной сцены |

Наш существующий рендер катсцен v61 сохранён отдельно. Его наработки по материалам, DDS mip-цепочкам и освещению не подменяются этим map viewer. Сравнение двух рендеров на одинаковых кадрах не проводилось, поэтому утверждения о визуальном превосходстве нет.

Локальная проверка CASC 19 октября: один и тот же NativeLib.galaxy, сборка 5.0.17.98310. Content/encoding keys и первые 24 байта совпали. Первый поиск: CascLib 3603 мс, ModKit 2794 мс; inspect: 1 и 3 мс. Это одиночные измерения с дисковыми кэшами, не устойчивый рейтинг скорости. CascLib вернул localeFlags 4294967295, адаптер ModKit — недоступное значение 0. Подробности: локальный `work/modkit-integration/casc-comparison.json`.

## Исправление невидимых баз и уступов

Первый кадр был ошибочно построен из старой `Agria_Vasya_Fedya_Test`, ещё без нативных cliff cells. Проверка перенесена на упакованную `Agria_Vasya_Reinforcements_v8.SC2Map` с нативными уступами и рампами.

Дополнительно найден дефект Host: URI преобразованного UVM сохранял имя исходного `.m3`. У больших файлов профиль UVM расположен дальше 64 KiB окна распознавания. Поэтому обычный glTF codec побеждал UVM и не публиковал скелет, анимации и материалы. Изолированное исправление `scripts/modkit/platform-patches.mjs` сохраняет расширение `.uvm` в синтетическом URI, проверяет точное место замены и отказывается менять неизвестный код. Оно применяется при установке, а хеши изменённых файлов записываются в provenance. Это не замена модельного парсера или рендера.

На фактическом CommandCenter UVM confidence изменился с 0.01 на 0.98; восстановлены 23 материала, 142 элемента skeleton и 34 анимации. CPU-кадр v8 визуально проверен: видны оба командных центра и стенки уступов. Сцена содержит 93 cliff pieces, из них 6 ramp pieces. Число pieces не равно числу `<cc>` исходной карты: правила генерации отсеивают клетки без отдельной стенки и добавляют углы рамп.

Источник результата и ограничения остаются явными. `complete: false` сохраняется при отсутствии optional Regions/navigation/pathing-компонентов; отдельные эффекты и особенности материалов могут не воспроизводиться. Действительный WebGL/GPU-кадр в этой интеграции не проверялся.

## Кандидаты для будущего PR в ModKit

Воспроизведение: большой UVM, профиль за пределами 64 KiB, URI `memory+uvm:...m3`; обычный glTF теряет rig/material facets. Исправленный URI выбирает UVM. PR не создан и ничего в upstream не отправлено. Защита записи, build/cache integrity и транзакции остаются в нашем проекте независимо от принятия будущих PR.

## Расширение TERRAIN — 19 октября

Подключены недостающие публичные format/navigation API той же зафиксированной версии ModKit. Их бинарные парсеры, сериализаторы, расчёт footprint и поиск маршрутов используются напрямую. Наши согласованные редакторы высот, текстур, воды, скрытия, клифов и рамп сохранены. В upstream добавлены только явные package exports `map/format`, `map/navigation`, `map/overview`; это часть воспроизводимого `compatibility.patch`, без второго набора парсеров.

| Возможность | Команда / операция | Реальные границы |
|---|---|---|
| Запрет прохода, запрет строительства, clear-path override | `terrain.pathing.paint`, `terrain.pathing.fill` | Маски `CellAttribute_Pnp/Pnb/Pcl`, кисти rectangle/circle/polygon/corridor. `block=255`, `erase=0`. Заливка обходит соседние клетки с одинаковым paint-байтом; клиф сам по себе не ограничивает эту заливку |
| Отсутствующая CellAttribute-маска | Параметр `template` у кисти либо `templates` в плане | Копируется проверяемый native header донора; сетка целевой карты начинается пустой. Header не угадывается, чужая проходимость не переносится |
| Статическая навигация и PNG | `terrain.navigation.preview` | Terrain, cliff/ramp, painted masks и footprint размещённых объектов. Data/CASC, наследование, локальные изменения каталога и зависимости читает ModContext. `catalog=false` отключает эту загрузку |
| Сырые paint-слои | `painted.set` в `terrain.modkit.plan_file` | Два byte-канала `PaintedPathingLayer`/`PaintedCreepLayer`, native сетка 512×512. Это не rebuild навигации или полноценная симуляция creep |
| Vertex-color | `vertexColor.set` | Значения существующих stroke entry/index в декодируемом VTCL. Произвольная RGBA-кисть поверх неизвестной структуры не заявляется |
| Мелкий поверхностный декор | `fluff.add`, `fluff.set`, `fluff.remove` | Native DLFT записи x/y/type 0…7; отдельный формат, не произвольная Actor-модель |
| Полные native группы дорожных/жёстких плит | `hardTile.replace`, `hardTile.repair` | Замена полных групп HRDT v102 с сохранением явных opaque полей; исправление повторных group keys. Неполный декодированный layout отклоняется. Генератор дорожного spline не добавлен |
| PATH-кэш | `pathing.hints` | Сырые uint16 значения `t3SyncPathingInfo`. Upstream не подтверждает их самостоятельного влияния в игре; для запретов используются CellAttribute |
| Палитры и texture block sets | `palette.author` | Original authoring обновляет terrain XML, CTerrain/CTerrainTex и регистрацию GameData. Байты texture masks остаются прежними: порядок каналов нужно задавать осмысленно |
| Подбор native диагональной рампы | `terrain.ramp.fit` | До 16 вариантов по crossing points и направлению uphill. Это подбор подходящего donor profile, не свободная генерация любого mesh |
| Перенос/расширение native рампы | `ramp.template` | Original placement/widening; согласованы HMAP, SMAP height/mask, CLIF и LFCT. Whole two-cell lattice; widening только квалифицированных диагональных профилей; v115 identity XY/Z и поддержанные версии companions. Opaque Terrain/hard-tile handles отклоняются |
| Массовый декор | `terrain.decorate` | Делегирование нашему `placement.scatterDoodads`: seed, weighted palette, высота/уклон/текстура/вода/расстояния/exclusion zones, до 5000 объектов за запрос |
| Привязка объектов к поверхности | `terrain.objects.snap` | Наш `placement.snapToTerrain` сохраняет различие unit offset Z и absolute doodad Z. Возвращает Placement plan |

Общие команды: `terrain.modkit.capabilities`, `terrain.modkit.inspect`, `terrain.modkit.plan`, `terrain.modkit.plan_file`, `terrain.modkit.apply`. Для большого запроса выгоднее JSON-файл: до 100 операций / 1 MiB. `inspect` возвращает страницу, а не целый бинарный слой; у HRDT параметр `blockIndex` открывает записи одной группы. Большие списки не отправляются в модель.

Для наших height/texture/water/cliff brushes остаётся прежний цикл `terrain.plan_file → terrain.apply → terrain.save`. Для добавленных операций: `terrain.modkit.plan_file → terrain.modkit.apply(dryRun:false) → modkit.save(file)`. `modkit.save` теперь действительно сохраняет целую группу binary-транзакции; раньше эта общая команда сохраняла только text draft, вопреки описанию. SHA-проверки исходников, диска и донора, backup и идемпотентное повторное apply сохранены. Само планирование файлы не меняет.

Пример кисти на уже существующей маске:

```json
{
  "directory": "maps/MyMap",
  "layer": "noPathing",
  "mode": "block",
  "area": {
    "type": "circle",
    "center": { "x": 30, "y": 20 },
    "radius": 4
  }
}
```

Это аргументы `terrain.pathing.paint`; результат — `planId`. До apply можно вызвать `terrain.navigation.preview` с тем же directory и planId. Изменяющий Data палитры план сначала нужно сохранить либо использовать `catalog=false`: анализ не смешивает новый terrain/catalog plan со старыми эффективными Data. Несохранённые Objects/Data также отклоняются при включённом каталоге. Snapshot Data неизменяемый; чистые binary terrain drafts могут анализироваться отдельно от сохранённого каталога.

`terrain.decorate` и `terrain.objects.snap` возвращают планы Placement: применять через `placement.apply`, затем `modkit.save` на возвращённом Objects-файле (для text draft также подходит `ui.save`). Это тот же существующий координатор расстановки, а не второй scatter/writer.

### Что у нас сохранено и что можно предложить upstream

Наши согласованные terrain companions, точная семантика высоты объектов, seeded scatter с фильтрами, короткие MCP планы, guarded apply/save и контроль зависимостей остаются поверх ModKit. Для этих задач готовый общий формат-reader не заменяет уже работающий authoring workflow. Реалистичные будущие PR: публичные terrain API exports, атомарная координация companions при donor-ramp transfer, ограниченные preview/plan ответы и тестовые примеры интеграции. Это дополнение к подтверждённому UVM URI fix выше; PR пока не создавались.

### Проверка на реальной карте

Свежий stdio MCP импортировал копию `Agria_Vasya_Reinforcements_v8.SC2Map`, добавил CellAttribute-запрет, сохранил группу, перечитал native bytes, добавил три fluff-записи, проверил заливку в dry-run, проверил карту и экспортировал архив с повторным открытием. Тестовая копия: `work/ModKit_Terrain_Test.SC2Map`. Оригинальная Agria не изменялась.

Навигация прочитала из Data/CASC 34 сущности и 8 footprint за два раунда, без неразрешённых зависимостей. Найден 21 объект-препятствие. До запрета: 2037 доступных / 1839 пригодных для строительства клеток; после: 1941 / 1743. Между одинаковыми точками (27,27) и (37,37) маршрут находился до правки и не находился после неё. PNG сохранены вместе с receipt `work/modkit-integration/terrain-mcp-acceptance.json`.

Локальное время: первый navigation PNG с холодной загрузкой каталога — 29 с, второй после изменения карты — 7.7 с; кисть 160 мс, заливка 124 мс, apply 184–303 мс, сохранение 285–373 мс, экспорт 1.4 с. Эти цифры включают соответствующую работу MCP на этом компьютере; они не являются сравнением движков или гарантией времени. Текстовые счётчики `modkit.usage` не равны оплаченным токенам модели.

Тесты проверяют original native round-trip, сохранение неизвестных байтов, отказ от opaque VTCL/HRDT, flood fill, footprint зданий/ресурсов/декора, NoDoodadFootprint, diagonal fitting/widening и согласованный перенос companions, stale/dry-run/save и регистрацию каталогов.
