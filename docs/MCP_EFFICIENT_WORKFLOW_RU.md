# Быстрый авторинг карт через MCP

Для работы над картой используйте профиль `workflow` и один сеанс MCP на серию действий. Карта меняется только инструментами MCP; тонкий клиент `scripts/mcp-session.mjs` лишь держит stdio-соединение и сокращает ответы на экране.

```powershell
node scripts/mcp-session.mjs --root K:\path\to\Map.SC2Map.components
```

Клиент принимает по одной JSON-команде на строку. `steps` передаются в существующий `modkit.batch`; операции выполняются последовательно, по исходным схемам и с обычными ограничениями устаревшего плана. До выполнения батча статические аргументы всех шагов проверяются на соответствие схеме. Выход — короткие квитанции.

Одиночная команда `{"tool":"data.validate","args":{}}` тоже маршрутизируется через `modkit.batch`: это позволяет обращаться к инструментам, скрытым в профиле `workflow`. Для `data.report.page` клиент автоматически показывает выбранную страницу. Если нужны конкретные поля другого ответа, укажите `"select":["fieldName"]`.

```json
{"id":"check","steps":[{"id":"terrain","tool":"terrain.validate","args":{}},{"id":"objects","tool":"placement.validate","args":{}}]}
{"id":"data","steps":[{"id":"check","tool":"data.validate","args":{}},{"id":"issues","tool":"data.report.page","args":{"reportId":{"$from":"check.reportId"},"section":"diagnostics","offset":0,"limit":10},"select":["total","items","nextOffset"]}]}
{"command":"close"}
```

`data.validate` и `data.batch` по умолчанию возвращают число ошибок и первые восемь диагностик. Полный результат сохраняется как сжатый снимок в `.sc2mcp-output/data-reports`; `data.report.page` читает страницы этого снимка без повторной проверки каталогов. Старый полный формат доступен через `response:"full"` при прямом MCP-вызове вне профиля `workflow`; `modkit.batch` сокращает и такой ответ. Большие ответы дороже по времени, памяти и передаче данных.

Для размещения сотен объектов сначала формируйте один план/пакет и проверяйте координаты, затем применяйте и сохраняйте его через `modkit.batch`. Поиск моделей и Data лучше делать серией запросов в том же сеансе: в журнале Agria первые поиски занимали десятки секунд, а следующие запросы того же типа часто менее секунды. После завершения смыслового блока запускайте валидацию и превью один раз, вместо повтора после каждого объекта.

`modkit.usage` измеряет только текст MCP. Ответы больше 1 МиБ не токенизируются фоновым счётчиком, но их байты и длительность сохраняются. Этот счётчик не показывает расход токенов модели. Проверка структуры terrain также не доказывает, что нативные клифы замкнуты визуально: проблемные стыки требуют сохранённой редактором пары карты «до/после» и просмотра в SC2.

Чтобы оценить именно текст, который вывел этот клиент, задайте `SC2_MCP_SESSION_METRICS` с путём к локальному JSONL-файлу до запуска. Для каждого ответа туда пишутся длительность, число байт запроса/короткого ответа и число обычных текстовых токенов `o200k_base` в ответе клиента. Это ближе к видимому результату, но всё равно не включает системные инструкции, историю диалога, изображения, размышление или тарификацию модели. Без переменной дополнительная токенизация клиента не запускается.
