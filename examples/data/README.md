# Data example

`CodexUnitApply.json` is one `data.apply` request. `Base.SC2Data/GameData.xml`, `Base.SC2Data/GameData/UnitData.xml`, and `ComponentList.SC2Components` show its native component-directory output.

`ReaperBurnApply.json` is a verified six-operation batch that preserves the Reaper's native damage, adds a refreshing periodic burn buff, and plays the stock Hellion `FireImpact.m3` model on the damaged unit. `ReaperBurnData.xml` is the exact XML emitted by that request.

`ReaperBurnAndDamageTextureApply.json` is the compact form: two recipe operations expand to the same burn graph plus a reversible 40%-Life texture monitor. `ReaperBurnAndDamageTextureData.xml` is generated by `npm run data:example`; `ReaperBurnAndDamageTextureValidation.json` records the exact static validation result and operation economy. The two `CodexReaper_*.dds` files are intentional user-supplied asset paths, not claims about an innate Reaper texture filename.
