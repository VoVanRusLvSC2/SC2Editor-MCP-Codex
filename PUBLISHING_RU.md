## Что необходимо сохранить

| Файлы | Назначение |
| --- | --- |
| `src/` | MCP, GUI, освещение, катсцены, парсеры и тесты исходного кода |
| `package.json`, `package-lock.json`, `tsconfig*.json`, `eslint.config.mjs` | Установка зависимостей, сборка и проверки |
| `scripts/` | Сборка native backends, генерация registries и проверки |
| Исходники `native/`, pinned revisions, StormLib и все сторонние notices | Воспроизводимая сборка MPQ/CASC; собранные `native/bin/` не нужны в Git исходников |
| `windows/` | Launcher и инструкции подключения |
| `schema/` и выбранные runtime-файлы `generated/` | Схемы и registries, которые сервер читает во время работы; права на импортированные данные проверяются отдельно |
| `vendor/blizzard-models/{src,browser,dist}/`, metadata, GPL и notices | Текущий рендер использует и JS из `dist`, и browser chunks; весь vendor каталог удалять нельзя |
| `LICENSE`, `CREDITS.md`, `THIRD_PARTY_LICENSES.md`, README, актуальные руководства | Авторство, сторонние условия, запуск и использование |

Точный список кандидатов создаёт `npm run publication:audit` в
`work/publication/audit.json`. Это проверка состава, **не команда публикации**:
она не делает commit/push, не меняет индекс Git и не копирует игровые ресурсы.
Категория `review` означает нужный файл, для которого остаются вопросы
прав/происхождения; `local` означает файл вне предложенного публичного состава.

`npm run publication:prepare` создаёт отдельную локальную копию всех файлов
`candidate` и `review`, включая сторонний код и его notices, в новом каталоге
`work/publication/source-package-*`. Каждый файл копируется без изменений и
проверяется побайтно. Manifest с SHA-256 и точным путём находится отдельно в
`work/publication/prepare.json`. Экспорт не меняет рабочие исходники или индекс
Git; не удаляет предыдущие копии; не делает commit/push. Это состав для обзора
следующего коммита, а не разрешение нерешённых publication holds.

Runtime whitelist `generated/` находится в `publication-policy.json`:
AI/Cutscene/Data/Text/Font/Trigger/Galaxy registries, `data-xsd-index/`, словарь
`o200k_base` и его MIT notice. Остальные отчёты `generated/` не нужны для запуска
сервера. Удаление всей папки `generated/` сломает часть инструментов.

## Что оставить локально

`work/`, `output/`, `release/`, `dist/`, `dist-runtime/`, `node_modules/`,
кэши, браузерные captures, одноразовые проверки и отчёты, старые плееры,
скриншоты, DMP/EXE/Ghidra/декомпиляция и игровые M3/M3A/DDS/FXA/audio.
Fixtures и примеры рассматриваются отдельно: среди них есть байты игровых
компонентов. Проверка оставляет такие входы локально, а не удаляет их.
Полная локальная тестовая серия может нуждаться в этих fixtures.

Наши вспомогательные TXT не входят в whitelist. Явно запрошенный актуальный
статус `docs/RENDER_STATUS_V42_RU.txt` включён как отдельное исключение.
**Лицензии TXT сохраняются**:
`LICENSE-GPL-2.0.txt`, `LICENSE-CascLib.txt`, `TIKTOKEN_LICENSE.txt` и notices
в сторонних исходниках. Текстовые файлы внутри поставленных сторонних исходников
сохраняются вместе с ними, чтобы не потерять notices и build inputs. Удалять все
`*.txt` одним правилом нельзя; например, `CMakeLists.txt` нужен для сборки.

## Что мешает полному публичному push сейчас

Обязательное упоминание в использующем проекте — дополнительное условие, поэтому
лицензия больше не названа BSD-2-Clause. Совместимость этого условия с
объединённой поставкой GPL-2.0-only renderer не предоставлена. До push нужен
совместимый вариант renderer/его разрешение либо отдельное решение владельца
прав об условиях нашего кода; требование упоминания автоматически не отменено.

1. У импортированного Surface Toolkit `core/` и `format/` нет установленной
   лицензии на распространение. Нужны условия исходного автора или замена
   этой реализации; без этих файлов текущий terrain-модуль неполон.
2. У поставленного GPL renderer отсутствуют некоторые локальные зависимости
   и полный исходный build entry point. Для объединённой публичной поставки
   нужно проверить и обеспечить комплект соответствующих исходников.
3. Для импортированных схем/registries и исследовательских производных нужен
   отдельный разбор состава и прав. Наша лицензия не перелицензирует эти данные.

Поэтому audit честно возвращает `readyForPublicPush=false`. Сам список файлов
и лицензия уже подготовлены; весь рабочий каталог пока не является проверенным
публичным пакетом. Не следует просто выполнять `git add -A` и push.

Перед будущей публикацией проверь `git diff --cached --name-only`: `.gitignore`
не убирает уже отслеживаемые игровые fixtures и отчёты из истории Git. Если они
уже были закоммичены, отдельный чистый репозиторий/экспорт может быть удобнее
переписывания общей истории. Проверка состава не сканирует прошлые коммиты и не
является полной проверкой секретов.

Сборка кода проверяется `npm run build:release`. Для работы native backend
нужны `npm run archive:build` и `npm run casc:build` с соответствующим native
toolchain. Игра устанавливается пользователем отдельно. Опубликованных
asset-embedded HTML-плееров в исходной поставке быть не должно.
